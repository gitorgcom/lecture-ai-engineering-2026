## 宿題

- 取り組んだレベル：基礎 

- やったこと（変更したファイル・設定・処理、または設計した取得方法）：  
app/agent.py の TREE_INSTRUCTIONS を変更

- 比較した質問と、固定した条件（モデル・対象資料など）：  
第2回の「LoRA/QLoRA」の質問
モデルは gemini-3.5-flash-lite
対象資料は第1〜3回の本講義214ページ
Treeモードで変更前後を比較

- 結果（変更前後の回答・根拠、`--trace`の出力、時間・トークン数・生成API推定費用など）：  

app/agent.py の TREE_INSTRUCTIONS に下記を追加し変更
本文にある数値や用語の表現を勝手に変更してはならない。  
本文に記載がなく不明な点がある場合は「不明な箇所があるため、さらなる調査が必要」と回答する。  
→ 数値は安定したが、QLoRA を QLORAとするなど、回答の用語生成にゆらぎが生じた。  

app/agent.py の TREE_INSTRUCTIONSをさらに改善
本文にある数値を勝手に変更せず、そのまま使用する。  
本文にある略語の綴り（小文字と大文字の違いなど）を変更せず（QLoRAの場合はQLoRAと記載するなど）そのまま使用する。  
本文に記載がなく不明な点がある場合は「不明な箇所があるため、さらなる調査が必要」と回答する。  
→ 3回の出力で安定してQLoRAと回答するようになった。  

変更前は、`QLOAR` の誤記や「数千億・数十億パラメータ」といった本文にない表現が混ざっていた。  
変更後は、3回の連続した回答で QLoRA の表記で安定、`数千億` のような本文にない規模表現は出なくなった。

--trace は 3回とも browse_tree({}) → browse_tree({'node_id': 'lec02-main'}) → browse_tree({'node_id': 'lec02-main-s045'}) → browse_tree({'node_id': 'lec02-main-p052'}) で、同じ流れで p.52 に到達した。  

実行結果は 1回目が 5.38秒・9,619 / 261・5回・$0.003538、2回目が 4.56秒・9,619 / 302・5回・$0.003641、3回目が 4.11秒・9,619 / 240・5回・$0.003486 だった。  

- 改善した例と、残る失敗・制約：  

改善した例は、`QLOAR` のような誤記が消え、LoRA と QLoRA の表記が安定したこと、`数千億` のような本文にない記述が出なくなったこと。

残る制約は、同じ p.52 を根拠にしていても、言い回しや説明順は少しずつ変わることがある点である。指示文でかなり抑えられるが、今回の改善方法では、LLMの生成ゆらぎを完全になくすことは難しい。

- 気づき・疑問：  

指示文を強めると、本文にない数値や誤記は減らせるという結果となった。
今回は、instructionにピンポイントで問題点を記載したため改善に至ったが汎用性が低い。
LLMの生成ゆらぎを完全にはなくせないため、回答の細かな揺れは残る。
Tree は根拠ページへの到達は安定しているので、今後は回答生成の安定性をどう上げるかが課題。
